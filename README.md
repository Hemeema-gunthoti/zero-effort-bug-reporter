🤖 Zero-Effort Bug Reporter


An AI-powered automation pipeline that captures test failures, analyzes them using Groq (LLM), and creates or updates Jira tickets automatically—with smart deduplication, priority escalation, and proxy-resilient file attachments.

🚀 Overview
When CI/CD tests fail, engineers often spend significant time manually creating bug reports, copying stack traces, and assigning tickets. Zero-Effort Bug Reporter eliminates this bottleneck by:

Reading test failure metadata generated by pytest (via conftest.py).

Using Groq's high-speed LLM to analyze the stack trace and console logs.

Classifying severity and priority via a hybrid (rules + AI) approach.

Creating structured Jira tickets with all relevant details, or updating existing tickets if the bug is a recurrence.

✨ Key Features

🧠 AI-Powered Analysis: Sends stack traces and logs to Groq to extract root cause, affected component, error type, and suggested fixes.

🔄 Smart Deduplication: Uses a 3-strategy JQL search (Label → Summary → Component) to find existing Jira tickets before creating new ones.

⬆️ Auto-Escalation: Automatically bumps the priority of recurring bugs and posts a "Recurrence Detected" comment with fresh evidence.

⚖️ Hybrid Classification: Determines severity (Critical/High/Medium/Low) using deterministic rules first, ensuring consistent handling of payment/auth failures, with AI as a tiebreaker.

📎 Proxy-Resilient Attachments: If direct file uploads to Jira are blocked by a corporate proxy (e.g., Zscaler returning 403), the agent automatically zips the file and retries the upload.

👤 Auto-Assignment: Maps affected components to specific team members using a team_mapping.json configuration.

🛠️ How It Works

A[CI/CD Test Failure] --> B[conftest.py writes failure_metadata.json]    
B --> C[main.py Orchestrator]    C --> D[FailureAnalysisAgent]    
D --> E1[Load Stacktrace & Logs]    D --> E2[Groq AI Analysis]    D --> E3[Hybrid Classification]    D --> E4[Determine Assignee]    D --> F[Generate Bug Report JSON]    
C --> G[JiraMCPClient]    G --> H{Duplicate Check via JQL}    
H -- New Bug --> I[Create Jira Ticket + Attach Files]    H -- Existing Bug --> J[Escalate Priority + Add Recurrence Comment]

🏃 Usage

Automated (CI/CD Pipeline)

The tool is designed to run automatically after your test suite completes. Your conftest.py should generate 

artifacts/failure_*.json files, then trigger the orchestrator:


python main.py
Manual (Single Failure Analysis)

You can also analyze a single failure metadata file directly:


python agent/failure_agent.py artifacts/failure_test_login_20240101_120000.json



🧠 AI & Classification Logic

Groq Analysis: The agent sends a strictly prompted request to Groq, demanding a raw JSON response. It defensively strips 
markdown fences (```json) in case the model hallucinates them. If Groq fails, it falls back to a basic string-parsing 
analysis.

Hybrid Classification:

Rules first: Scans the combined text (stack trace, component, user impact) for critical signals (e.g., "payment", "data 
loss" → Critical/P1).

Escalation overrides: Login/authentication failures are automatically escalated to at least High/P2.

AI tiebreaker: Used for edge cases not caught by the rules.

🛡️ Proxy & Error Resilience

Jira API Versioning: Automatically falls back from v3 to v2 endpoints if API calls fail (e.g., Atlassian deprecating /rest/api/2/search returning 410 Gone).

Zscaler/Corporate Proxy Blocks: If attaching a screenshot or log directly returns a 403 Forbidden (common with Zscaler intercepting multipart uploads), the agent automatically zips the file in memory and retries the upload as file.zip.

Label Verification: After creating a ticket, it reads the ticket back to verify the dedup label was actually saved. If missing, it forces an update.
